# Передача задачи №4 — этап 0 Polza

Дата: 2 ноября 2026. Этот файл предназначен для продолжения в новом чате проекта.

## Что уже сделано и подтверждено

- Закрытый стенд запускается командой `npm run dev` и поднимает Next.js, PostgreSQL-проверку и отдельный worker.
- На главной странице `http://127.0.0.1:3000/` есть закрытый экран запуска тестов, таблица истории и состояние worker. Если нет включённых моделей, форма запуска заблокирована — это защита от случайных расходов.
- Очередь PostgreSQL использует транзакционный захват `FOR UPDATE SKIP LOCKED`.
- Ключ Polza используется только сервером из локального `.env`; в браузер не передаётся.
- Для видео подтверждена полная автоматическая цепочка: очередь → Polza → загрузка MP4 → FFmpeg → WB-файл → история.
- FFmpeg использует `FFMPEG_PATH` из локального `.env`, если команда `ffmpeg` не найдена через `Path`.
- WB-выход для автоматического теста подтверждён через `ffprobe`: H.264, 810×1080, `yuv420p`.
- Временные ошибки Polza `408`, `429`, `502`, `503` worker ставит на безопасный повтор с паузой. Сетевой обрыв и клиентский тайм-аут не повторяются автоматически: у Polza нет ключа идемпотентности и исходный запрос мог быть принят.
- 2 ноября 2026 выполнена локальная проверка `npm run test:retry-safety` без обращения к Polza: имитации `429` и `503` создают отложенный повтор, `Retry-After` имеет приоритет, лимит попыток останавливает повторы, а `NETWORK_ERROR` и `CLIENT_TIMEOUT` остаются финальными. `typecheck`, `lint` и `build` также пройдены.
- `npm run typecheck`, `npm run lint` и `npm run build` проходят.

- Обнаружен и исправлен дефект безопасного захвата: прежде задача оставалась `QUEUED` во время HTTP-вызова и могла быть захвачена повторно после минутной аренды. Теперь захват сразу переводит её в `PROCESSING`, а аренда равна 650 секундам — больше документированного десятиминутного окна Polza. `npm run test:retry-safety`, `npm run typecheck`, `npm run lint` и `npm run build` проходят.
- До исправления по одному тесту Nano Banana был подтверждён лишний запрос на `3 ₽`, а по спорному GPT Image — один лишний запрос на `4 ₽`; второй GPT Image на момент записи ещё обрабатывался у Polza. Исходная GPT-задача переведена в `BLOCKED` с причиной `AMBIGUOUS_SUBMISSION`: автоматический повтор для неё запрещён до сверки окончательного результата и стоимости в кабинете.
- Не повышать лимит ключа и не менять ключ автоматически. Оставшиеся тесты запускать только после обновления дневного лимита либо в следующий день, строго по одному и только после явного согласия администратора.
