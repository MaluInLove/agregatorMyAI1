# Учебный AI-агрегатор

Закрытый локальный стенд этапа 0 для проверки серверной интеграции с Polza. В текущей задаче подготовлены каркас приложения, PostgreSQL, первоначальный администратор, локальное хранилище и отдельный worker.

## Однократная настройка Windows

1. Установите Node.js 24 LTS и PostgreSQL 17. PostgreSQL должен быть запущен как служба Windows.
2. Добавьте `C:\Program Files\PostgreSQL\17\bin` в пользовательскую переменную `Path`, затем откройте новый PowerShell. Команда `psql --version` должна сработать.
3. Установите FFmpeg и добавьте его каталог `bin` в `Path`. Убедитесь, что `ffmpeg -version` срабатывает. FFmpeg понадобится на этапе обработки видео.
4. Создайте базу данных, например:

   ```powershell
   psql -U postgres -c "CREATE DATABASE ai_aggregator;"
   ```

5. Скопируйте `.env.example` в `.env` и укажите корректные `DATABASE_URL`, `INITIAL_ADMIN_EMAIL` и пароль из 12+ символов. Реальные секреты в Git не добавляйте.
6. Установите зависимости:

   ```powershell
   npm install
   ```

7. Проверьте подготовку компьютера:

   ```powershell
   npm run check:env
   ```

## Запуск

```powershell
npm run dev
```

Команда проверяет PostgreSQL, применяет миграции, создаёт первоначального администратора при его отсутствии, создаёт `var/storage` и одновременно запускает веб-приложение и worker. Стенд доступен по адресу [http://127.0.0.1:3000](http://127.0.0.1:3000) и намеренно не слушает локальную сеть.

Если порт `3000` занят другим локальным проектом, в текущем окне PowerShell выберите другой порт:

```powershell
$env:PORT = 3001
npm.cmd run dev
```

Первоначальный администратор создаётся только один раз по email из `INITIAL_ADMIN_EMAIL`; повторный запуск не создаёт копию и не изменяет пароль существующей записи. Экран входа появится вместе с приглашениями и сессиями в задаче №6.

## Полезные команды

```powershell
npm run check:env
npm run db:migrate
npm run db:seed-admin
npm run typecheck
npm run lint
npm run build
```

`npm run dev` требует только доступную PostgreSQL-базу. `check:env` дополнительно проверяет наличие `psql` и FFmpeg, чтобы сообщить о неполной подготовке среды до работ с видео и резервными копиями.

## Безопасность

- `POLZA_API_KEY`, строка подключения PostgreSQL и пароль первоначального администратора находятся только в `.env` и не имеют префикса `NEXT_PUBLIC_`.
- Исходный код браузера не получает серверные переменные окружения.
- Локальные результаты будут храниться в игнорируемом Git каталоге `var/storage`.
- Для будущих резервных копий PostgreSQL используйте `pg_dump` из каталога PostgreSQL `bin`; Docker для локальной разработки не требуется.
