# Учебный AI-агрегатор

Закрытый локальный стенд этапа 0 для проверки серверной интеграции с Polza. В текущей задаче подготовлены каркас приложения, PostgreSQL, первоначальный администратор, локальное хранилище и отдельный worker.

## Однократная настройка Windows

1. Установите Node.js 24 LTS и PostgreSQL 17. PostgreSQL должен быть запущен как служба Windows.
2. Добавьте `C:\Program Files\PostgreSQL\17\bin` в пользовательскую переменную `Path`, затем откройте новый PowerShell. Команда `psql --version` должна сработать.
3. Установите FFmpeg и добавьте его каталог `bin` в `Path`. Убедитесь, что `ffmpeg -version` срабатывает. Если worker не видит обновлённый `Path`, укажите полный путь к `ffmpeg.exe` в `FFMPEG_PATH` в `.env`. FFmpeg понадобится на этапе обработки видео.
4. Создайте базу данных, например:

   ```powershell
   psql -U postgres -c "CREATE DATABASE ai_aggregator;"
   ```

5. Скопируйте `.env.example` в `.env` и укажите корректные `DATABASE_URL`, `INITIAL_ADMIN_EMAIL` и пароль из 12+ символов. Реальные секреты в Git не добавляйте.
6. Установите зависимости:

   ```powershell
   npm install
   ```

7. Проверьте подготовку компьютера:

   ```powershell
   npm run check:env
   ```

## Запуск

```powershell
npm run dev
```

Команда проверяет PostgreSQL, применяет миграции, создаёт первоначального администратора при его отсутствии, создаёт `var/storage` и одновременно запускает веб-приложение и worker. Стенд доступен по адресу [http://127.0.0.1:3000](http://127.0.0.1:3000) и намеренно не слушает локальную сеть.

Если порт `3000` занят другим локальным проектом, в текущем окне PowerShell выберите другой порт:

```powershell
$env:PORT = 3001
npm.cmd run dev
```

Первоначальный администратор создаётся только один раз по email из `INITIAL_ADMIN_EMAIL`; повторный запуск не создаёт копию и не изменяет пароль существующей записи. Экран входа появится вместе с приглашениями и сессиями в задаче №6.

## Диагностика стенда

Worker записывает heartbeat в PostgreSQL при запуске и далее не реже раза в минуту. Для локальной технической проверки доступны агрегированные данные очереди и последний сигнал worker по адресу [http://127.0.0.1:3000/api/diagnostics](http://127.0.0.1:3000/api/diagnostics). Ответ не содержит промптов, API-ключей, ответов Polza или подписанных ссылок. На главной странице стенда есть закрытый запуск включённых моделей и история задач.

## Polza и модели-кандидаты

После запуска `npm run dev` стенд добавляет в базу стартовых кандидатов моделей из ТЗ, но оставляет их выключенными. Перед включением в настройках нужно заменить пометку `candidate/...` на подтверждённый технический ID Polza, выбрать хотя бы одного разрешённого провайдера и указать ценовой потолок. Это исключает случайный платный запрос по неподтверждённой конфигурации.

Ключ `POLZA_API_KEY` добавляется только в локальный `.env`. Его нельзя передавать в браузер, коммитить в Git или отправлять в чат.

Повторы безопасны только для явных ответов Polza `408`, `429`, `502` и `503`: worker ставит задачу обратно в очередь с паузой и сохраняет ошибку. При сетевом обрыве или клиентском тайм-ауте задача завершается ошибкой без автоматического повтора, потому что Polza не предоставляет ключ идемпотентности и исходный запрос мог быть принят.

Проверить эту политику локально, без сетевого обращения к Polza, можно командой `npm run test:retry-safety`.

## Полезные команды

```powershell
npm run check:env
npm run db:migrate
npm run db:seed-admin
npm run typecheck
npm run lint
npm run build
npm run test
```

`npm run dev` требует только доступную PostgreSQL-базу. `check:env` дополнительно проверяет наличие `psql` и FFmpeg, чтобы сообщить о неполной подготовке среды до работ с видео и резервными копиями.

`npm.cmd run test` запускает все автоматические проверки: правила очереди и файлов, безопасные повторы и интеграционные сценарии в отдельной БД из `TEST_DATABASE_URL`. Рабочая база и настоящее файловое хранилище в этих тестах не используются.

## Docker для будущего VPS

Docker Compose из `compose.yaml` поднимает PostgreSQL, разовый сервис миграций, веб-приложение и отдельный worker. Для него скопируйте `.env.docker.example` в `.env.docker`, заполните секреты и выполните:

```powershell
docker compose --project-name ai-aggregator --env-file .env.docker up --build -d
```

По умолчанию порт опубликован только на `127.0.0.1`; для VPS нужен HTTPS reverse proxy. Полная процедура резервного копирования и восстановления PostgreSQL, локального хранилища и S3 описана в [DEPLOYMENT.md](DEPLOYMENT.md).

## Безопасность

- `POLZA_API_KEY`, строка подключения PostgreSQL и пароль первоначального администратора находятся только в `.env` и не имеют префикса `NEXT_PUBLIC_`.
- Исходный код браузера не получает серверные переменные окружения.
- Локальные результаты будут храниться в игнорируемом Git каталоге `var/storage`.
- Для будущих резервных копий PostgreSQL используйте `pg_dump` из каталога PostgreSQL `bin`; Docker для локальной разработки не требуется.
